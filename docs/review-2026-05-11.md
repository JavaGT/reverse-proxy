## Remaining Issues (MEDIUM severity)

### 1. No error handler on ALPN-routed TLS sockets (`src/server.js:234-240`)
TLS sockets that emit `'error'` before or during handoff to http1Server/http2Server have no handler. Add `socket.on('error', () => socket.destroy())` before the ALPN check.

### 2. Port validation on register (`src/routes/register.js:2-5`)
Port values `0`, `-1`, `999999` accepted without range check. Validate `1 ≤ port ≤ 65535`.

### 3. No auth on admin server (`src/admin.js:101-121`)
Admin API (`/api/register`, `/api/deregister`) is unauthenticated. Currently bound to `127.0.0.1` only. If access is expanded, add `x-api-key` check.

### 4. Default API key (`src/config.js:4`)
`'dev-secret-change-me'` used when env var not set. Log a warning at startup if using the default.

### 5. `_sent` auth flag pattern is fragile (`src/middleware/auth.js:4-17`)
If `apiKeyAuth` returns without calling `reply.code().send()`, execution falls through. Refactor to throw or return boolean.

### 6. Health-check response errors unhandled (`src/healthcheck.js:9-16`)
`http.get()` response stream can emit `'error'` (corrupt chunked encoding). Add `res.on('error', ...)`.

### 7. Certificate file writes not atomic (`src/tls.js:146-147`)
Write to `.tmp` files then `rename` to prevent partial writes on crash.

### 8. `close` timeout does not clean up orphaned inner servers (`src/server.js:255-265`)
10s timeout force-resolves the promise but http1Server/http2Server remain open. Currently safe because `process.exit(0)` follows. If used as library, add server destruction after timeout.

### 9. No method restriction on control-plane routes (`src/index.js:13`)
`/register`, `/deregister`, `/services` accept any HTTP method. Consider enforcing POST/DELETE/GET as appropriate.

## Remaining Issues (LOW severity)

- `isMain` detection via `.includes()` is fragile
- Dangling cleanup/health timers if `start()` is imported and fails
- `readBody` error from size limit returns "Invalid JSON" instead of "Request body too large"
- Close callback could fire twice; guarded by `closed` boolean (already fixed)
- Proxied request `res.on('finish')` listeners accumulate on persistent HTTP/2 streams
- Cleanup race: stale check then deregister could remove a freshly-registered service
- `dnsRecordIds` map grows without bound if challengeRemoveFn is never called
- Porkbun API key may be logged in error output
- Admin server has no CSRF protection (not applicable since localhost-only)
- `extractSubdomain` and `extractBaseHost` in `src/utils/host.js` are unused
